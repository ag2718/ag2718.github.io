Modern computers, powered by chips known as CPUs, are extremely powerful machines that can execute what we tell them to; on a surface level, the idea of a machine that can just perform arbitrary computations sounds almost magical. Instead of focusing on the complications and pragmatic details of modern CPUs, we'll walk through what digital computation even means and then use our understanding to build an extremely basic CPU.

### Understanding digital computation

The central idea behind computation is that physical systems can be engineered to reliably transform representations of information, often numbers. That's quite an abstract statement so let's walk through it with a basic example.

#### A mechanical computer

The simplest computers use mechanical components. To design a computer that doubles a number, you could connect gears with radii 5 and 10 inches: if the 10 inch gear rotated by $x^\circ$, the 5 inch one would rotate by $2x^\circ$[^1]. To multiply a number by two, you'd rotate the 10 inch gear (input). Then, the machine would compute by rotating the 5 inch gear, whose angular rotation could be measured as the output. In this way, a symbolic mathematical operation (multiplying by 2) is represented by a physical computation.

[^1]: This is because the outer edges, or circumferences, of both gears move by the same distance. Thus, the angle traveled is inversely proportional to the radius.

#### Digital circuits

Eventually, scientists and engineers began developing circuits that manipulate electrical signals to perform computation, using voltages rather than angles to represent information. Unlike the slow turn of a mechanical wheel, electrons move at nearly the speed of light, allowing for incredibly fast computation. 

However, working with voltages directly was problematic: electrical noise and measurement errors led to unreliable computation. Engineers designing these systems thus opted to ignore exact voltage values and instead binarize voltages as either LOW or HIGH based on certain thresholds. These *digital circuits* enabled deterministic and noise-resistant computation. The binary voltages are known as *bits*, represented as either 0 (LOW) or 1 (HIGH).

Transistors are the key modern component that govern these circuits, functioning as tiny electrical switches whose state depends on their input. These components can be used to form small circuits called *logic gates*, which have incoming wires (inputs) and outgoing wires (outputs).

A powerful property of logic gates is that they can be thought of as functions. Binarized voltages on incoming wires cause transistors within these gates to switch on and off, producing certain output voltages on outgoing wires. Since these voltages map directly to *bits*, we can think of logic gates as taking in bits, computing some mathematical function on them, and outputting the resulting bits. The specific function depends on how the transistors are arranged inside the gate.

Below are the foundational logic gates and the operations they perform.

| Gate | Associated Function |
|------| ------------------- |
| AND  | $$f(x, y) = \begin{cases} 1 & \text{if both } x \text{ and } y \text{ are } 1 \\ 0 & \text{otherwise} \end{cases}$$ |
| OR   | $$f(x, y) = \begin{cases} 1 & \text{if at least one of } x \text{ or } y \text{ is } 1 \\ 0 & \text{otherwise} \end{cases}$$ |
| NOT  | $$f(x) = \begin{cases} 1 & \text{if } x = 0 \\ 0 & \text{if } x = 1 \end{cases}$$ |

These logic gates can be connected to form any digital circuit! We can write the application of these gates as functions `AND(x, y)` or as operators `x AND y`. One particularly interesting example is a *multiplexer*, which is the equivalent of the extremely powerful conditional statement in hardware. A multiplexer, or MUX, can take in a "control bit" and two values, outputting the first one if the control bit is 0 else the second one. This can be implemented like so:

`MUX(c, a, b) = ((NOT c) AND a) OR (c AND b).`

When `c = 0`, we have:

```logic
MUX(0, a, b) = ((NOT 0) AND a) OR (0 AND b)
             = (1 AND a) OR (0 AND b)
             = a OR 0
             = a
```

Similarly, when `c = 1`, we have:

```logic
MUX(1, a, b) = ((NOT 1) AND a) OR (1 AND b)
             = (0 AND a) OR (1 AND b)
             = 0 OR b
             = b
```

The key takeaway is that fundamental gates like AND, OR, and NOT can be combined to perform arbitrary complex bit manipulations, including even conditional selection with MUXs!

#### Circuits that remember

However, a crucial limitation of these circuits is that they are *stateless*: their outputs depend only on the current inputs. If an input changes, the output changes immediately, and the circuit has no memory of the previous input. This matters because many computations require memory. If we want to compute the running sum of inputs received, there's no way to do this without memory of previous inputs!

In digital circuits, this type of memory is implemented by special components called *flip-flops* that store bits across time. A periodic electrical signal, called a clock, functions like a metronome. On each tick (clock cycle), flip-flops update their stored values to match their inputs. Between clock ticks, flip-flops hold their stored values constant, allowing other circuits to reliably read the stored information from the previous cycle, even as the flip-flop's inputs change [^2].

[^2]: The idea of discrete timesteps is *fundamental* to our systems of computing – we naturally think of algorithms and programs as sequences of computations.

We'll now solve the running sum problem by using a flip-flop whose output is added to the circuit input, which is then fed back as an input to the flip flop (forming a loop of sorts). Then, in between clock ticks, the circuit will take the previous stored sum, add the current input to it, and store it back in the flip flop.

While this running sum problem was simple, using stateful circuits vastly expands the types of computational circuits we can build [^3].

[^3]: In fact, it can be shown that all algorithms are computable using this "state machine" approach, where we have access to a state that can be persisted over timesteps.

#### Bitstring representations

The inputs and outputs of digital circuits are *bitstrings*, or strings of 0s and 1s. A bitstring of length $n$ is really just a convenient way to group $n$ separate bit signals together – for example, an 8-bit input is just 8 individual wires carrying HIGH or LOW voltages (bits).

While bitstrings may seem rudimentary, we can define schemes that allow us to represent abstract ideas and quantities of arbitrary complexity with them. The key insight is that we can *interpret* these bit patterns to mean whatever we want, as long as our circuit is designed to manipulate them accordingly.

For instance, a length $n$ bitstring can be viewed as a base-2 representation of integers, ranging from $0$ to $2^{n}-1$. For example, $00100_2 = 4$ (since $0 \cdot 16 + 0 \cdot 8 + 1 \cdot 4 + 0 \cdot 2 + 0 \cdot 1 = 4$). The term "$n$-bit integer" refers to an integer represented by this type of bitstring. We can then build a circuit to add two $n$-bit integers (which are really just bitstrings of length $n$) using the standard digit-by-digit addition algorithm learned in elementary school. The physical circuit has no notion of "addition": we interpret the binary voltage signals to be numbers, designing a circuit that adds them as such.
### What is a CPU?

*A CPU is a stateful digital circuit that can execute different operations based on its inputs*. Unlike specialized circuits like an adder (which only adds numbers), a CPU is designed to be flexible: it takes in both an *operation* to perform and the *arguments* for that operation. This combination of operation and arguments is called an *instruction*.

Since CPUs are digital circuits, instructions must be encoded as bitstrings – just like we encoded integers using base-2 representation earlier. We then need to structure the CPU circuit to properly interpret this instruction encoding and perform operations accordingly. 

This flexibility is what makes CPUs so powerful. A single piece of hardware can perform addition one moment, multiplication the next, and countless other operations – enabling the general-purpose computing we rely on every day. In contrast, a fixed circuit like an adder can only ever add numbers.

### Let's build a CPU!

To see this in action, let's build an extremely simplified CPU that can perform arithmetic operations on integers. Our CPU will have 128 storage elements, each of which stores a single bit. We divide this bit storage into 16 groups of 8-bit integers, each of which is termed a "register". We group bits into 8-bit "registers" because that's enough to represent integers 0-255, which is convenient for our examples. 16 registers gives us enough working space to hold intermediate values. (Modern CPUs have much larger registers and also many more of them.)

#### Defining an instruction set

The first thing we need to do is define the behavior of our CPU. This is done through defining an *instruction set*, or the list of instructions our CPU is capable of performing. To keep it simple, let's support four simple instructions:
- `ADD x1 x2 y`: Add the integers stored in registers `x1` and `x2` and store in register `y`
- `MUL x1 x2 y`: Multiply the integers stored in registers `x1` and `x2` and store in register `y`
- `PUT val y`: Put the specified integer `val` into register `y`
- `GET y`: Output the value in register `y` as the circuit output

Our CPU should be able to execute any arbitrary "program", or list of these commands. Let's write a simple program in this instruction set that computes the sum $\sum_{i=1}^{4} i^2$. 

```instructions
PUT 1 r1       // r1 = 1
PUT 2 r2       // r2 = 2
PUT 3 r3       // r3 = 3
PUT 4 r4       // r4 = 4

MUL r1 r1 r5   // r5 = 1 * 1 = 1
MUL r2 r2 r6   // r6 = 2 * 2 = 4
MUL r3 r3 r7   // r7 = 3 * 3 = 9
MUL r4 r4 r8   // r8 = 4 * 4 = 16

PUT 0 r0       // r0 = 0
ADD r0 r5 r0   // r0 = 0 + 1 = 1
ADD r0 r6 r0   // r0 = 1 + 4 = 5
ADD r0 r7 r0   // r0 = 5 + 9 = 14
ADD r0 r8 r0   // r0 = 14 + 16 = 30

GET r0         // Output final result: 30

```

> These types of low-level instructions are referred to as *assembly*. Humans generally program in higher-level languages like C which have more powerful constructs (e.g. loops, functions, etc.). To bridge this gap between these representations, a tool called a *compiler* converts higher-level code to assembly. Compilers feature extensive optimizations that find the most efficient set of assembly instructions that map to the input code.

#### Inputting instructions into our CPU

We discussed that these "instructions" are the input to our CPU. 


For example, `PUT 0 r0` would be passed into the CPU, followed by `PUT 1 r1`. But our CPU, being a digital circuit, takes in bits as inputs. We then need to convert our instructions to bitstrings through a clever encoding scheme. At a high level, we'll encode both the instruction type and arguments as bitstrings, and then concatenate them together.

To encode instruction type, note that we have four different instructions: we could use all the combinations of 2 bits to denote these. For example, `00` is `ADD`, `01` is `MUL`, `10` is `GET`, and `11` is `PUT`.

Now, different operations have different arguments:

- `ADD` and `MUL` instructions three registers (two input, one output). Register indices go from 0-15, which can be represented by a 4-bit integer. Then, we pass in 14 total bits for these instructions: 2 for the instruction type, and $4 * 3 = 12$ for register labels. As an example, `ADD r1 r4 r5` is `00·0001·0100·0101`.
- `PUT` has an integer and a register: we pass in one integer (8 bits) along with a register index (4 bits). As an example, `PUT 13 r1` is `11·00001101·0001`.
- `GET` works identically to `PUT`, except we don't need to pass in an integer value (can leave it as zeros). `GET r2` is `10·00000000·0010`.

We've thus developed an encoding that allows us to pass in any instruction as a **fixed length bitstring** (for this CPU, 14 bits)! When we receive a `GET` instruction, we expect the CPU output on the next timestep (cycle) to be the corresponding value. Our CPU is then a (very complicated) digital circuit that represents a stateful function with a 14-bit input, 8-bit output, and a 128-bit internal state.

> In a real CPU, instructions are stored in memory and fetched one at a time. For simplicity, we'll assume our toy CPU receives one instruction per clock cycle as its input. Real CPUs don't actually have a notion of "output" either: they interact with the rest of the computer through the operating system, which we won't discuss here.

#### A minimal CPU sketch

Let's walk through how we can design a circuit that executes the above instruction set. Recall that AND, OR, and NOT logic gates are building blocks made from transistors. Thus, we can describe the CPU circuit in terms of these functions, knowing that any such expression can be directly translated into a transistor circuit.

> This is a toy circuit that is *extremely simplified* for pedagogical purposes. We're intentionally ignoring any inefficiency! We're also hand-waving some of the small implementation details for the sake of simplicity.
{: .prompt-warning }

Let's define some utility circuits we'll need to use. These can all be constructed from clever combinations of NOT, AND, and OR gates.
- `MUX[n](c, v_0, v_1, v_2, ..., v_{2^n-1})`: Outputs the $c$-th value $v_c$, where $c$ is interpreted as an $n$-bit integer. This generalizes the previous MUX we discussed, and can actually be built out of smaller muxes.
- `EQUAL(a, b)`: outputs 1 if all bits of `a` and `b` match. We will also write this as `a == b`.

A set of 14 bits is passed into our circuit, so the first step is to figure out which input bits we need to reference for operation and argument information. To do this, we'll label different chunks of bits with meaningful names so we can refer to them easily – we're essentially *decoding the encoding* from earlier!

```instructions
// inst[i:j] gets bits from position i to j, inclusive
// 0-indexed starting from the left.

// The structure of the PUT/GET instructions is separate from ADD/MUL instructions.

OP_CODE = inst[0:1]

REG_INP1_ARITH = inst[2:5]  // first input register index for ADD / MUL operations
REG_INP2_ARITH = inst[6:9]  // second input register index for ADD / MUL operations
REG_OUT_ARITH = inst[10:13] // output register index for ADD / MUL operations

VAL_PUT = inst[2:9]         // 8-bit integer value for PUT operation
REG_PUT = inst[10:13]       // register index to perform PUT operation at
REG_GET = inst[10:13]       // register index to perform GET operation at
```

---

Let's first implement the digital logic for executing PUTs. To do this, we will add logic gates connecting the input bits to each register. These sets of logic gates, for each register, will:

1. Check if (a) the `OP_CODE` matches `11`, the `PUT` operation code and (b) whether `REG_PUT` matches the register index.
2. If it does, set the register to the value `VAL_PUT`.

For the register at index `i`, the step 1 check happens as: `set_reg = (REG_PUT == i) AND (OP_CODE == 11)`. Then, we only update that register if `set_reg` is 1: `reg[i]_new = MUX(set_reg, reg[i], VAL_PUT)`, meaning we only set the register to the new value if our conditions are met. Effectively, the CPU only performs a `PUT` operation on the correct register – if the input doesn't represent a `PUT`, this does nothing!

---

For GET, we'll add logic gates to:

1. Check if the `OP_CODE` matches `10`, the `GET` operation code.
2. If it does, set the output to the value stored in the register at index `REG_GET`.

The step 1 check happens as: `is_get = (OP_CODE == 10)`. To get the value from the correct register, we use a MUX with all 16 register values as inputs: `reg_value = MUX[4](REG_GET, reg[0], reg[1], ..., reg[15])`. Then, we only update the output if `is_get` is 1: `out_new = MUX(is_get, out, reg_value)`, meaning we only set the output to the register value if our conditions are met[^4].

[^4]: In doing this, we're assuming that the previous output is stored state that we can access: our stored state is actually $128 + 8 = 136$ bits to be 100% precise.

---

Designing ADD and MUL will build on ideas from both GET and PUT but in more complicated ways: we'd get the values stored in `REG_INP1_ARITH` and `REG_INP2_ARITH` using GET-style circuits, connect those as the inputs to the respective adder and multiplier circuits, and then connect the outputs to registers using a PUT-style circuit. The adder circuit can be designed using the bit-by-bit addition and carry algorithm (similar to how you might add numbers in base-10 manually). Multipliers are a lot more complicated, finding clever ways to represent multiplication through bit operations.

With that, we've described a CPU that can execute any program of these four instructions! Specifically, if we pass in instructions (encoded as bitstrings) consecutively, this digital circuit will "execute" them and update the output after receiving a `GET` instruction.

We could extend our CPU further to include more complicated instructions: comparison operators like $<$, $>$, $\leq$, $\geq$ can be implemented in terms of logic gates and also allow us to do more sophisticated conditional logic using MUX circuits.

### The end-to-end system

As a high-level overview, CPUs are complex digital circuits that compute a stateful function that represents instruction execution. Bitstring inputs encode abstract instruction information, which the CPU circuit decodes and executes through complex networks of logic gates. Performing this process over instructions sequentially allows us to execute powerful programs, enabling applications ranging from video game renderers to web browsers to numerical solvers.

Modern CPUs are *far* more complex than our toy example. They load programs and data from external memory, execute instructions out of order (jumping between different parts of code based on conditionals and loops), and optimize performance through advanced tricks. Yet despite this complexity, the fundamental principle of dynamically executing instructions on fixed digital circuits (CPUs) powers nearly all computing technology across the world.
